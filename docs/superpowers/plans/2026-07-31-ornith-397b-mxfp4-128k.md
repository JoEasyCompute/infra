# Ornith 397B MXFP4 128K Profile Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add an experimental `ornith-397b-mxfp4-128k` NVIDIA profile that attempts a 128K-context Ornith 397B run on eight 32 GB GPUs with MXFP4 weights, DCP4, FP8 KV cache, and single-sequence execution.

**Architecture:** Extend the wrapper's existing profile-default model instead of creating a second execution path. General memory-control CLI options feed the same effective configuration, validation, Docker command, and artifact writers used by existing profiles; the static shell harness proves command shape, failure ordering, override behavior, and regression safety without GPU hardware.

**Tech Stack:** Bash, Docker CLI, vLLM OpenAI server, Harbor 0.20.0 through uv, JSON metadata written by embedded Python 3, shell regression tests.

## Global Constraints

- Keep `ornith-35b-practical` as the default and preserve its effective command.
- Preserve `ornith-397b-published` and its BF16 reproducibility boundary.
- Pin `olka-fi/Ornith-1.0-397B-MXFP4` at revision `04940815e4ddf15e2b7cc4710e81e3cecc25540b`.
- Pin the profile to NVIDIA image `vllm/vllm-openai:v0.25.1-cu129`.
- Use `terminal-bench/terminal-bench-2-1@6`, Terminus-2, Qwen3 vLLM parsers, JSON Harbor parsing, temperature/top-p `1.0`, 32 task CPUs, and 49,152 MB task memory.
- The canonical topology is eight selected GPUs, TP8, and DCP4; fewer than eight GPUs or TP that does not use every selected GPU is invalid.
- Require `TP_SIZE % DCP_SIZE == 0`.
- Use 131,072 maximum context, FP8 KV cache with calculated scales, 0.95 GPU memory utilization, one vLLM sequence, eager mode, language-model-only mode, Harbor concurrency one, zero CPU offload, and 300 GB minimum Docker-root free space.
- Reject AMD before Docker activity and reject hardware runs below approximately 250 GiB aggregate selected VRAM before downloads.
- Treat valid overrides as modified runs and keep dry-run side-effect free.
- Do not claim guaranteed eight-RTX-5090 compatibility until a real hardware smoke test passes.
