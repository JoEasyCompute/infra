# Ornith 397B Published Profile Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add an explicit `ornith-397b-published` benchmark profile while preserving `ornith-35b-practical` as the default and documenting the limits of comparison with the published score.

**Architecture:** Resolve and validate `--profile` in a pre-scan, apply that profile's defaults once, then run the existing parser so every explicit option wins regardless of argument order. Keep backend selection independent, extend the existing Harbor command and metadata writers with effective profile values, and lock behavior through the hardware-free static harness.

**Tech Stack:** Bash, Docker CLI command construction, Harbor 0.20.0 through `uv`, JSON metadata generated by Python 3, shell-based regression tests.

## Global Constraints

- Keep `ornith-35b-practical` as the default with model `deepreinforce-ai/Ornith-1.0-35B`, revision `5df2ed3f675c7beaa490328cc70bb573b65fb660`, dataset `terminal-bench@2.0`, and 16,384-token context.
- Pin `ornith-397b-published` to model revision `5e3e761811e804c295c1d3c0ce68b21da6154209` and dataset snapshot `terminal-bench/terminal-bench-2-1@6`.
- Published-profile defaults are 131,072-token context, `qwen3_xml` tool parser, `qwen3` reasoning parser, Harbor JSON parser, temperature/top-p `1.0`, 32 CPUs, and 49,152 MB RAM.
- Explicit CLI options override profile defaults regardless of argument order.
- Profiles do not select the backend, GPU list, or tensor-parallel size.
- Dry-run must not create artifacts or reveal `HF_TOKEN`.
- Do not claim exact reproduction of the reported 77.5 score because the original Harbor patch, dataset snapshot, and absolute four-hour timeout override are not published.
- Preserve existing NVIDIA and AMD runtime command behavior.

- [ ] **Step 2: Pre-scan and validate `--profile`**

Implement:

```bash
discover_profile() {
    local args=("$@")
    local index=0
    while (( index < ${#args[@]} )); do
        case "${args[$index]}" in
            --profile)
                (( index + 1 < ${#args[@]} )) || die "--profile requires a value"
                PROFILE="${args[$((index + 1))]}"
                index=$((index + 2))
                ;;
            --)
                break
                ;;
            *)
                index=$((index + 1))
                ;;
        esac
    done
}
```

Validate the final discovered name, then apply its defaults before the normal parser. The normal parser consumes `--profile` without reapplying defaults.

- [ ] **Step 3: Parse and validate explicit profile-controlled options**

Retain existing model, revision, dataset, agent, max-model-length, tool-parser, and reasoning-parser cases. Validate resource values as positive integers and sampling values as finite numeric values in their accepted ranges.

- [ ] **Step 4: Compute whether effective values differ**

Implement `update_profile_modified` by comparing all effective profile-controlled fields with the selected profile's defaults. This keeps `false` when an operator explicitly repeats a default and sets `true` only when behavior actually differs.

- [ ] **Step 5: Preserve custom-model revision safety**
